# 수용 시험 규격

PRD v0.5 §11 수용 기준(AC-1~13)과 성능·보안·청소년 지침의 판정 기준이다. Review & Test agent와 사용자가 같은 기준으로 판정하도록, 모든 항목에 사전 조건·절차·기대 결과·증거·판정자·기록 양식을 적는다. 최종 실행은 #38에서 하고, 개별 이슈는 담당 AC의 해당 부분을 완료 기준으로 쓴다. 고정 자료는 [`fixtures/acceptance/`](../fixtures/acceptance/README.md)에 있다.

## 1. 공통 규칙

- **증거 위치**: `docs/evidence/<항목>/<YYYY-MM-DD>.md`
  - 내용: 실행 환경(커밋, Node 버전, 접속 경로 localhost/터널), 절차별 결과, 스크린샷·로그 경로, 자동 테스트 이름
  - 대화 원문·개인 파일 내용은 넣지 않는다
- **두 런타임**: "두 런타임: 예"인 항목은 아래 양식 A로 Claude Code와 Codex 결과를 각각 기록해야 통과다.
- **판정자**:
  - 자동 테스트로 확인하는 부분은 Review & Test agent(CI 결과 + 실행 기록)
  - 실기기·실계정 부분은 관리자(사용자)가 수행하고 Review & Test agent가 기록을 검토
- **통과·실패**: 모든 절차의 기대 결과가 맞고 증거가 있으면 통과다. 하나라도 어긋나면 실패이고, `bug` 라벨 이슈를 만든다.

### 기록 양식 A (두 런타임)

```markdown
| 절차 | Claude Code (모델) | Codex (모델) | 증거 |
|---|---|---|---|
| 1 | 통과/실패 — 관측 | 통과/실패 — 관측 | 스크린샷·테스트 이름 |
판정: 통과/실패 · 판정자: · 커밋:
```

### 기록 양식 B (단일 실행)

```markdown
| 절차 | 결과 | 관측 | 증거 |
|---|---|---|---|
판정: 통과/실패 · 판정자: · 커밋:
```

## 2. 수용 기준별 절차

### AC-1 접속과 화면 구조
- **두 런타임**: 아니오 · **기록**: 양식 B · **판정자**: 관리자 수행, Review & Test agent 검토
- **사전 조건**: 운영 Mac에 서비스와 `cloudflared`가 실행 중이다. Access 정책에 가족 이메일이 있다. 가족이 아닌 시험용 이메일 1개를 준비한다.
- **절차**:
  1. 집 안 브라우저에서 `http://localhost:3000`에 접속한다.
  2. 휴대폰 LTE에서 `https://chat.2prostream.com`에 접속한다.
  3. 시험용 비가족 이메일로 Access를 시도한다.
- **기대 결과**:
  1. 앱 로그인만 거치고 사이드바·대화·아티팩트 패널의 3단 구조가 보인다.
  2. Access 이메일 코드 → 앱 로그인 → 같은 구조가 보인다(모바일은 서랍).
  3. Access 단계에서 거부된다.
- **증거**: 단계별 스크린샷, Playwright 레이아웃 테스트 이름(#13)

### AC-2 파일 인용
- **두 런타임**: 예 · **기록**: 양식 A · **판정자**: Review & Test agent
- **사전 조건**: 아들 계정, #48·#23의 PDF·HWP fixture 각 1개
- **절차**:
  1. 두 파일을 올리고 "두 문서를 비교해서 요약해줘"를 보낸다.
  2. 답변의 모든 파일 인용을 하나씩 누른다.
- **기대 결과**:

  2. 누르면 뷰어가 그 위치를 열고 문장을 강조한다. 인용 내용이 그 위치 원문에 실제로 있다.
- **증거**: 인용별 "위치 / 원문 일치 여부" 표, Playwright 테스트 이름(#24)

### AC-3 검증 실패 인용 표시
- **두 런타임**: 예 · **기록**: 양식 A · **판정자**: Review & Test agent
- **사전 조건**: fixture 서버가 `citations/page-claims.html`과 404를 돌려주는 `/missing.html`을 제공한다. 상태별 생성 방법은 [`citations/cases.md`](../fixtures/acceptance/citations/cases.md)에 있다.
- **절차**:
  1. **자동**: FakeRuntime이 `cases.md`의 다섯 상태를 각각 만들게 하고 화면을 확인한다.
  2. **실제 런타임**: page-claims 페이지를 주고 "이 페이지에 없는 내용도 섞어서 요약해줘"를 보낸다.
- **기대 결과**:

  2. 실제로 확인되지 않은 인용은 모두 ⚠️ 상태다.
- **증거**: 상태별 스크린샷·테스트 이름, 실제 런타임 인용 상태 표

### AC-4 금융 표·차트

- **절차**:

- **기대 결과**:

  - 모든 숫자에 출처·기준 시각이 붙는다. 휴장일이면 최근 거래일로 표기한다.

### AC-5 예약 실행과 알림

- **사전 조건**: 아내 계정, 휴대폰 PWA 알림 허용
- **절차**:
  1. **7일 게이트(#57)**: "매일 08:00 관심 종목 브리핑" 예약을 7일간 둔다.
  2. **예외 자동 시험(#33, 가짜 시계)**:
     - 실패 → 2분 뒤 재시도 1회

  3. 켠 직후 1회만 실행되고 이력에 남는다.
- **증거**: 날짜별 "예정 / 시작 / 결과 저장 / 휴대폰 수신" 시각 표, 예외 시험 테스트 이름

### AC-6 권한 403과 공유 해제
- **두 런타임**: 아니오 · **기록**: 양식 B · **판정자**: Review & Test agent
- **사전 조건**: 사용자 A·B. A의 대화에 파일·아티팩트가 있다.
- **절차**:
  1. B로 A의 대화·메시지·파일 원본·파일 다운로드·아티팩트 `/a/:id`·`/a/:id/v/:ver/raw`·SSE를 직접 요청한다.
  2. A가 B에게 공유한다 → B가 SSE를 연다 → A가 공유를 해제한다 → B가 같은 요청을 다시 보낸다.
  3. 없는 ID를 요청한다.
- **기대 결과**: 1과 2(해제 후)는 403이고, 해제 즉시 열린 SSE가 닫힌다. 3은 404다.
- **증거**: 권한 매트릭스 테스트(#10, #29) 결과

### AC-9 연결 종류별 동작

### AC-13 이메일 추가·비활성화와 Access

## 3. 성능 측정 규격 (NFR 성능)

| 지표 | 측정 시작 → 끝 | 조건 | 표본 | 합격 (PRD 그대로) |
|---|---|---|---|---|
| 첫 토큰 표시 | 전송 버튼 클릭 → 응답 첫 글자가 화면에 렌더링됨(Playwright, DOM 관찰) | 도구 호출 없는 고정 프롬프트 "한 문장으로 인사해줘" | 런타임별 30회, 로컬·터널 각각 | p95 ≤ 3초 |
| 사이드바·대화 열기 | 앱 로드 완료 후 사이드바 항목·대화 클릭 → 목록·메시지가 화면에 표시됨 | 대화 100개·메시지 50개 시드 | 각 20회 | **모든 표본** ≤ 500ms |
| 전환 후 첫 토큰 | 런타임 전환 직후 전송 클릭 → 첫 글자 렌더링 | 메시지 20개 대화 | 방향별 20회 | p95 ≤ 6초 |

- 측정 환경: 운영 Mac, 다른 무거운 작업 없음. 결과에 커밋·모델·시각을 적는다.
- 스크립트: `scripts/perf/`(#38에서 작성).
