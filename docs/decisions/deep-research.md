- 날짜: 2026-11-19
- 작성: Dev agent (Claude Opus 5.5), 계획: #211 본문(사용자 결정 1–6, 2026-11-19 승인)
- 관련: PRD FR-17(v0.8)·FR-5(출처)·FR-13(알림)·FR-9(사용량), `docs/decisions/sources.md`(#185·#186·#202 인용 규칙), `docs/ops.md` 50절, `docs/traceability.md`
- 범위: **1단계** — Claude 백엔드 전 과정 + 외부 백엔드 인터페이스. **2단계(후속 PR, TODO)** — 외부 Deep Research API(Gemini·OpenAI) 실제 연결.

## 1. 문제와 목표

"🔎 자료 조사"(#25)는 답변 규칙을 바꾸는 토글일 뿐, 여러 단계로 오래 조사하는 작업이 아니다. 깊이 조사는 한 질문을 **계획 → 승인 → 병렬 조사 → 보강 → 작성·검증 → 보고서**로 처리하고, 보고서의 모든 사실 문장이 서버가 확인한 인용을 갖게 한다. 외부 프레임워크(LangGraph, GPT Researcher 등)는 들이지 않고 **패턴과 프롬프트 아이디어만** 가져와 기존 도구(`web_search`·`web_fetch`·`cite`·`file_*`·아티팩트·알림) 위에 만든다. 새 의존성은 없다.

## 2. 핵심 결정: 서버가 오케스트레이션한다 (Agent SDK 서브에이전트를 쓰지 않음)

| 선택지 | 판단 |
|---|---|
| Agent SDK의 서브에이전트(`Task` 도구, `agents` 옵션)로 리드가 서브에이전트를 띄움 | **쓰지 않음.** (1) 보안 잠금(`runtime/lockdown.ts`)이 `Task`를 포함한 내장 도구를 모두 막고 우리 MCP 도구만 허용한다 — 서브에이전트를 열면 그 경계를 다시 설계해야 한다. (2) 동시 실행 수·서브에이전트별 도구 호출·시간 상한, 30분 하드 상한, 단계별 체크포인트·재시작 이어하기, 진행 이벤트를 **서버가 강제**할 수 없다(모델이 정한다). (3) FakeRuntime으로 결정적으로 시험할 수 없다. (4) Codex에는 같은 기능이 없어 런타임 독립 설계(D8)와도 어긋난다. |
| **서버가 여러 번의 Claude 실행을 직접 조율** | **채택.** 각 단계(리드 계획, 서브 연구자 하나, 리드 보강 판단, 작성자)는 **한 번 쓰고 닫는 세션**(`research/step.ts` — 기억 정리 #146의 일회성 세션과 같은 방식: 이어가지 않고, 끝나면 닫고, 런타임 상태는 삭제 작업에 넘겨 지운다)이다. 동시 실행은 서버의 풀(기본 3), 상한은 서버 타이머, 체크포인트는 DB 행이 맡는다. |

각 단계의 MCP 토큰은 `{사용자, 대화, 단계 id(research:<job>:<step>)}`로 묶이고 단계가 끝나거나 한도에 걸리는 즉시 폐기된다(#173 규칙). 토큰에는 **그 단계의 도구 목록과 호출 상한**이 실려, 우리 MCP 서버가 호출을 받는 시점에 검사·차감한다(`McpTokens.take` — 목록 밖 도구는 `skill_not_allowed`, 상한 초과는 `skill_quota`, 아무것도 실행되지 않음). SDK의 `tool_start` 관찰은 보조 장치다. `echo_time`처럼 MCP 패키지가 직접 답하는 도구도 같은 검사(`McpHost.mayCall`)를 거친다. 폐기된 실행의 웹 호출은 다음 검색 공급자로 넘어가기 전, 리디렉션 홉마다, 출처 저장 직전에 다시 확인해 멈춘다(`WebService` `alive`) — 이미 보낸 한 요청만 자기 시간 상한 안에서 끝나고 그 결과는 버린다.

**단계 종료**: 단계가 시간·한도·중지·하드 상한으로 멈추면 `runStep`은 그 순간까지의 글로 **즉시** 돌아오고, 그 순간 중단과 세션 닫기를 함께 시작한다(이벤트가 닫기를 기다리는 런타임도 닫힌다). 런타임이 멈추지 않거나 닫기가 늦어도 기다리지 않는다 — 닫기와 상태 지우기는 따로 추적되고(종료 시 최대 10초 기다림), 늦게 오는 이벤트는 결과를 바꾸지 못한다. **새 단계마다**(서브 연구자·보강·작성) 대화가 아직 Claude인지·연결이 있는지 다시 보고, 아니면 새 단계를 열지 않고 하던 단계를 멈춘다(`runtime_changed`). 실행마다 세대(`Live`)가 있어, 이전 실행이나 멈춘 실행의 늦은 결과는 작업 상태를 쓰지 못한다. 단계가 가져온 페이지(`sources`)와 인용(`citations`)은 그 대화의 것이 되어, 보고서 뒤 후속 대화에서도 `sources_list`·`cite`로 다시 쓸 수 있다.

## 3. 흐름 (`apps/server/src/research/engine.ts`)

1. **시작** `POST /api/conversations/:id/research {text, fileIds?, backend?}` — 새 대화 화면에서도(대화를 만든 뒤) 시작한다. 질문을 사용자 메시지(첨부 `file_ref` 포함)로, 카드를 답 메시지(`research` 부분, `jobId`)로 쓰고 `research_jobs` 행을 만든다. 대화 주인만, Claude 대화만(`research_claude_only` 409), 진행 중인 채팅 답이 없을 때, 한 사람당 동시 1개(`research_busy` 409 — 횟수 한도는 없음).
2. **계획**(도구 없음, 1분): 리드가 JSON 계획(제목·하위 질문 2–6개 — `RESEARCH_LIMITS.minSubQuestions`~`maxSubQuestions`, 계획·고치기·승인 모두 같은 규칙·범위·예상 시간) 또는 확인 질문 하나를 쓴다. 확인 질문은 한 번만(답을 받은 뒤에는 계획만 받아들인다). 계획은 카드에서 **승인 / 고치기 / 취소**. 승인 전에는 검색 도구가 없으므로 아무것도 가져오지 않는다(시험: 승인 전 `sources` 0행, 계획 단계 `tools: []`).
3. **승인** `POST /api/research/:id/approve {subQuestions?}` — 고친 하위 질문으로 바꾸고(id는 서버가 다시 매김, 첨부가 없으면 범위는 웹), **승인한 자료 범위**(웹·첨부의 합집합)를 체크포인트에 저장하고, **마감 = 승인 시각 + 30분 − 계획에 쓴 시간**을 정한다. 승인·확인 답·복구·단계마다 대화가 아직 Claude인지 다시 본다(Codex로 바뀌었으면 승인·답은 409 `research_claude_only`, 진행 중이면 `runtime_changed`로 끝나고 카드에 이유).
4. **조사**: 서브 연구자를 동시 3개까지. 각자 도구 12번·6분 상한, `web_search`·`web_fetch`(첨부 범위면 `file_search`·`file_read`). 찾을 때마다 바로 `NOTE {"claim","sourceId"|"fileId","quote"}` 줄을 쓰게 해서, 한도로 중간에 멈춰도 그때까지의 노트가 남는다. 서버는 노트의 구절을 **페이지 본문(`CitationStore.recheck`)이나 파일 추출 본문(`FileTools.check`)과 대조해 맞는 것만** 남긴다(같은 출처·구절은 하나로).
5. **보강**: 리드가 확인된 노트를 보고 빈 곳을 최대 3개 더한다 — 최대 2단계(`maxDepth`), 조사 예산이 8분 넘게 남았으면 한 단계 더(`extraDepth`, §11), 새 단계는 보강 판단 뒤에도 3분(추가 단계는 8분) 넘게 남았을 때만. 아니면 바로 작성(강제 마무리). 보강 질문의 범위는 **승인한 자료 범위 안으로 서버가 고정**한다(첨부만 승인했으면 웹 질문도 첨부로 — 웹 도구 0회). 범위가 기록되지 않은 체크포인트는 저장된 승인 계획에서 범위를 되살리고, 아직 묻지 않은(재시도할) 질문의 범위도 그 안으로 고정한다.
6. **작성·검증**: 작성자는 확인된 노트(하위 질문마다 번갈아 최대 45개 — 한 단계의 인용 상한 50개 안, 500자 넘는 구절은 버림)만 받고 `cite`/`file_cite`로 모든 사실 문장을 인용한다. 서버(`research/report.ts`)가:
   - #202와 같은 기준으로 자른다: `citationUnits`(화면의 마크다운 단위), `citationMarkers` 가운데 **파서가 일반 글로 본 곳**의 것만(`plainTextRanges` — 링크의 레이블·주소, 자동 링크 `<https://…/[1]>`, 인라인 코드 속 `[1]`은 표시가 아님), `sentenceSpans`(`결론이다.사실이다[1].`은 두 문장). 문장부호 뒤에 띄어 쓴 표시도 앞 문장의 것이다(`늘었다. [1] 수입도 …`의 `[1]`은 앞 문장),
   - 확인된(`verified`) 표시가 **하나도 없는 문장을 삭제**하고(인용 없음, 실패한 인용에만 기댐), 소제목도 문장마다 같은 검사를 하되, **문장부호(`. ! ? 。 ．`)로 끝나는 문장만 사실**로 본다(닫는 따옴표·괄호 너머까지 — `“수출이 줄었다.”`). 문장부호 없이 끝나는 것은 이름표라 표시 없이 남는다(`## 전력 시장(공급과 수요)`, `## 수출 동향(개요)`, `## 수출이 늘었다. 증가 원인` → `## 증가 원인`) — 어미로 추측하지 않는다. 소제목과 본문 줄은 **같은 문장 정리 과정**을 거친다(`cleanLine` — 소제목만 문장부호 없는 이름표를 남긴다는 점이 다르다): 원문이 아니라 **파서가 보여 주는 글**(`inlineLeaves` — 링크·강조·취소선 안의 글은 포함, 링크 주소는 제외)을 문장으로 나누고, 문장마다 **그 문장 범위 안의** 표시만 보고(같은 굵은 글씨 안의 다른 문장의 표시는 세지 않음), 확인되지 않은 표시와 같은 문장 안의 반복 표시만 뺀다(두 문장이 같은 출처를 각각 인용하면 둘 다 남음). 이미지의 설명(`🖼 alt`로 보임)도 보이는 글로 검사해 지우면 이미지째 뺀다. 지운 문장 때문에 보이는 글이 공백만 남은 링크·강조·취소선·이미지는 통째로 뺀다(`****`·`[](…)`가 남지 않음). 아무것도 지우지 않은 줄은 쓴 그대로 두고(인라인 코드 `[ -f report.md ]` 포함), 공백 정리는 실제로 지운 자리의 경계에서만 한다(`## ~~수출이 줄었다.~~ 증가 원인`·`## [수출이 줄었다.](https://…) 증가 원인` → `## 증가 원인`, 주소가 남지 않음). 소제목은 형식(ATX `##`, 밑줄형 `---`, 굵은 글씨만인 문단 — 뒤에 콜론이 붙은 `**증가 원인**:` 포함)과 상관없이 내용만 문장별로 정리한 뒤 다시 쓴다: ATX·밑줄형은 `##`~`######`, 굵은 이름표는 원래 모양(콜론 포함) 그대로. 마침표 바로 뒤의 숫자 링크 레이블(`늘었다[1].[2](https://…)`)은 다음 문장의 시작이다(보고서 경로에서만 — #202의 문장 경계는 그대로). 번호는 **본문이 확정된 뒤**(빈 절을 지운 뒤) 매기고, 대체 보고서 여부도 그 결과로 정한다 — 지워진 소제목의 번호가 남지 않는다,
   - 남는 문장에서 실패한 표시를 빼고, 표·코드 블록은 넣지 않으며(행마다 삭제로 셈), 내용 없는 소제목을 정리하고,
   - 표시를 **출처(페이지·파일)마다 하나씩** 나타난 순서로 1부터 다시 매긴 뒤(#233, 12절), 출처 목록(웹: 제목·사이트·주소, 그 아래 원문 구절들 / 파일: 이름, 그 아래 위치·구절들)과 "한계"(삭제한 문장 수, 시간 상한, 근거를 못 찾은 하위 질문)를 붙인다.
   - 작성자가 시간 안에 못 끝내거나 확인된 표시가 하나도 없으면 **확인된 원문 구절을 하위 질문별로 정리한 보고서**(대체 보고서)를 만든다 — 구절은 이미 서버가 대조한 것이고, 파일 구절의 위치는 검사가 찾은 위치(`locatorLabel`)다 — 작성자 프롬프트에는 그 위치(`place`, 보여 주는 쪽·줄)와 따로 **검사가 구절을 찾은 검색 단위 번호**(`page` — `file_cite`가 먼저 보는 단위, TXT는 여러 줄이 한 단위)를 넘겨 같은 곳에 인용된다. 작성자가 쓴 무인용 문장 수는 대체 보고서에서도 "한계"에 센다.
7. **결과**: 마크다운 아티팩트 하나, 카드 메시지에 요약(보고서 "요약" 절에서 표시를 뺀 글 — 출처는 보고서에)과 `artifact_ref`. 아티팩트·버전·카드 연결·메시지·`done`은 **한 트랜잭션**이고, 그 작업이 만든 보고서(`run_id = research:<job>`)가 이미 있으면 새 버전으로 이어 쓴다(두 개가 되지 않음). 알림 `research_done`.

## 4. 시간 (`RESEARCH_LIMITS`, `packages/shared/src/research.ts`)

| 예산 | 값 | 넘으면 |
|---|---|---|
| 계획 | 1분 | `plan_failed` |
| 조사(모든 단계) | 승인 후 20분, 그리고 마감 − 9분을 넘지 않음 | 하던 서브 연구자를 멈추고(노트는 남음) 작성으로 — "시간 상한으로 일부만 조사" |
| 서브 연구자 하나 | 6분, 도구 12번 | 그 연구자만 멈춤(`capped`) |
| 작성·검증 | 최대 8분, 마감 − 1분을 넘지 않음 | 쓴 데까지 검증, 확인된 것이 없으면 대체 보고서 |
| 하드 상한 | 마감(승인 + 30분 − 계획 시간) | 모든 단계 중단 신호 |

시간은 `research/clock.ts`의 `Clock`으로 재서 시험은 수동 시계(`ManualClock`)로 30분을 돌린다. 마감은 벽시계다 — 서버가 꺼져 있던 시간도 센다.

## 5. 체크포인트와 재시작

`research_jobs.state`(JSON)가 체크포인트다: 단계, 보강 단계, 하위 질문별 상태·확인된 노트, 시간 초과 여부. 단계가 끝날 때마다 쓴다. 시작할 때(`onReady → recover`) `planning`·`researching`·`writing`인 작업을 이어 간다 — 끝난 하위 질문은 다시 묻지 않고, 하던 것은 처음부터 다시 한다. 마감이 이미 지났으면 바로 작성(남은 시간이 없으면 대체 보고서), 확인된 노트가 없으면 `server_restart`로 실패. 종료(`preClose → shutdown`)는 단계만 멈추고 상태는 그대로 둔다.

## 6. 권한·공유·포크

자원 종류 `research`(대화의 권한 규칙): 주인만 시작·승인·고치기·확인 답·취소·중지(403), 공유받은 가족은 카드 메시지가 투영에 있을 때 `GET /api/research/:id`·`/events`만(`owned: false`, 버튼 없음). 공유 투영은 카드 메시지가 들어 있으면 그 작업의 보고서 버전(`research:<job>`)과 단계 인용을 실행의 답처럼 함께 넣는다 — live 공유·스냅숏·포크 모두 본문까지 읽는다. 아직 끝나지 않은 카드는 쓰는 중인 답처럼 다뤄 스냅숏 공유를 막는다(`share_run_in_progress`). 포크는 카드(`research` 부분)를 복사하지 않는다 — 요약과 보고서 아티팩트만. 권한 행렬(`test/helpers/permission-matrix.ts`)에 모든 경로가 있다.

## 7. 알림 (FR-13)

`research_done` / `research_failed`(실패·중지·근거 없음). 제목 "깊이 조사", 본문은 한 줄 — "깊이 조사가 끝났어요: <주제 앞부분>" / "깊이 조사를 마치지 못했어요: <주제> — <고정 이유>". 내용·출처는 넣지 않는다. 방해 금지 시간에는 `held`(알림함에만, 끝나면 묶어서 푸시), 알림 설정 "깊이 조사 알림"에서 종류별로 끈다(`notification_prefs.research_done`·`research_failed`). 누르면 `/c/<대화>#m-<카드>`.

## 8. 외부 백엔드 (2단계 — 인터페이스만)

진행 화면: SSE로 변경마다 작업 전체를 보내고, 작업에는 변경마다 1씩 오르는 `version`이 있어 화면은 더 새 것만 반영한다(늦게 온 조작 응답·조회가 덮어쓰지 않음). 열린 스트림은 종료(`preClose`) 때 모두 닫힌다.

`research/backend.ts`의 `ResearchBackend`: `id`·`label`·`external`·`available(user)`·`collect({question, plan, signal, deadlineAt}) → {claim, url, quote}[]`. 계획·작성·검증은 언제나 우리 것(Claude 리드·작성자, `cite`/`file_cite`)이고, 백엔드는 **찾은 것만** 돌려준다. 2단계에서 엔진은 외부 결과의 URL을 `web_fetch`처럼 대화 출처로 가져와 구절을 대조하고 맞는 것만 노트로 쓴다 — 내장 노트와 같은 기준. 관리자 설정(키 암호화 저장·허용 여부·청소년 기본 끔), 카드의 "기본(Claude) / 외부" 선택과 전송 안내는 2단계에서 붙인다. 1단계의 `ResearchBackendId`는 `claude`뿐이고 다른 값(요청의 `backend` 문자열)은 `backend_unavailable`(400)이다. **TODO(#211 2단계)**: Gemini Deep Research API, OpenAI deep research 연결.

## 11. 조사 한계 줄이기 (#234)

예시 보고서에서 확인하지 못해 지운 문장이 많고 근거 없는 하위 질문이 남았던 원인(공식 PDF를 못 읽음, 모델이 보는 본문은 앞 1만 자, 정확 대조 실패 시 바로 버림, 빈 하위 질문은 리드가 지목해야만 재조사)에 대한 결정:

- **PDF**: 웹 작업자는 바이트만 넘기고, 업로드와 같은 문서 추출기(#48 샌드박스, pdf.js — 이미 있는 고정 의존성)가 읽는다(`web/pdf.ts`). 웹 작업자 안에서 PDF를 해석하지 않는 이유: 그 샌드박스는 자기 폴더만 읽어 pdf.js를 불러올 수 없고, 신뢰하지 않는 PDF 해석은 네트워크가 없는 추출기 쪽이 더 안전하다. OCR은 끈다(페이지 가져오기가 몇 분씩 걸리지 않게). 읽지 못한 쪽은 U+E000으로 감싼 표시로 남기고, 그 표시는 **웹 PDF 출처(`application/pdf`)에서만** 본다(`hasGapMarks` — 정확 대조·`web_find`); 첨부 파일·다른 페이지의 U+E000은 평범한 글자다. 글자 수와 `web_find` 위치는 그 문자를 뺀 보이는 글 기준.
- **`web_find`**: 저장된 전체 본문을 문장으로 나눠(`citations/passages.ts`) 구절 전체가 든 문장을 먼저, 그다음 낱말이 많이 겹치는 문장을 앞뒤 문맥과 함께 준다. 결정적(모델·유사도 모델 없음)이고 인용 검증은 여전히 `cite`의 정확 대조다.
- **노트는 고치지 않는다**(리뷰 #237 4차, 마지막 결정): 한때 정확 대조에 실패한 노트의 구절을 가장 가까운 원문으로 바꿔 다시 대조했지만, 주장(claim)은 모델의 것 그대로 남으므로 바꾼 구절이 주장과 다른 뜻을 뒷받침할 수 있었다. 낱말 겹침 → 같은 순서의 낱말 → 형태 차이만 → "…" 이음과 숫자·한글 사이 공백만으로 네 번 좁혔는데도 매번 반례가 나왔다(부정·주체·부호, 격조사·통화·부등호·대소문자·하이픈, 숫자 사이 공백·소수점의 "…"·연산자·선택자 공백, 질문의 "?"를 지운 문장 잇기·앞 부정을 뺀 문장 뒷부분·식별자 공백·엔티티 이중 해석). **정확성이 재현율보다 앞선다**: 실패한 노트는 버리고, 그 주장은 "확인하지 못한 주장"(주장 전체의 해시로 구분, `claimKeyOf`)으로 재조사·보강 판단에 힌트로만 쓴다. 서브 연구자는 범위에 주어진 도구(웹: `web_find`·`web_fetch`, 첨부 파일: `file_search`·`file_read`)로 원문을 다시 찾아 그대로 복사한다(`subagent.md` v5).
- **자동 재조사**: 노트 0개 또는 출처 1개인 하위 질문을 한 번(`retried`) 다시 조사한다 — 보강 판단 전에, 같은 동시 상한·도구 한도 안에서, 조사 예산이 `minRoundMs` 넘게 남았을 때만. 보강 단계 수(`maxDepth`)에 세지 않고, 예산이 `extraRoundMs`(8분) 넘게 남았으면 보강 단계를 하나 더(`extraDepth`) 허용한다. 재시작 때 재조사 중이던 하위 질문은 첫 조사의 노트를 지키고 재조사만 다시 한다. 시간은 보강 판단 뒤 새 단계를 확정할 때, 그리고 재조사·보강 질문이 **실행 슬롯을 받을 때마다** 다시 본다. 노트 수와 마지막 종료 사유를 따로 기록해, 일시적 런타임 오류(`runtime_error`)는 한 번 재조사하고 계정 상태 오류(로그인·사용 한도·연결·권한·런타임 전환)는 노트가 있어도 하지 않으며, 확인된 것이 없을 때 작업의 실패 코드도 마지막 종료 사유(계정 오류 먼저, 모두 정상 종료면 `no_findings`)로 정한다. 시간 때문에 건너뛴 질문은 `skipped: "time"`과 `timedOut`으로 남겨 보고서가 시간 상한으로 센다. 실행 직전 범위를 승인 범위로 다시 고정해 오래된 체크포인트의 질문도 승인하지 않은 도구를 받지 않는다. 재조사가 새로 찾은 출처는 12개 상한 안에서 적어도 한 자리를 지킨다.
- **1차 자료 우선**: 서브 연구자 프롬프트에 정부·공공기관·대학 자료를 먼저 쓰라고 하고, 도메인으로 정한 `sourceType`을 도구 결과와 노트에 붙인다(`sourceTypeOf`, 공유 패키지 — 보고서 표시는 #233). 도메인은 정확성을 말해 주지 않으므로 검증에는 쓰지 않는다.

## 12. 설명 수준: 개요, 해석 문장, 시사점, 출처 묶기 (#233)

보고서가 사실 나열에 그쳤다. 참고: GPT Researcher(개요 → 섹션 → 시사점 결론), LangChain open_deep_research(섹션은 필요한 만큼 길게, 고유 URL 하나에 번호 하나, 섹션을 병렬로 따로 쓰면 글이 끊김), STORM(관점별 질문 → 개요 → 섹션), OpenAI(섹션마다 데이터에 근거한 추론).

- **개요 먼저, 한 번에 쓰기.** 작성 전에 리드의 개요 단계(`outline.md`, 도구 없음, 작성 예산의 1/5·최대 90초, 15초 미만이면 생략)가 섹션별 소제목·핵심 질문·쓸 노트·분석할 점을 낸다. 주어진 노트가 하나도 없는 섹션은 버리고, 2개 미만이면 개요가 없는 것으로 본다. 개요의 글(소제목 60자, 핵심 질문 200자, 분석할 점 300자)은 **조금도 바꾸지 않는다**(16차) — 쓴 그대로의 길이가 넘거나 줄바꿈(\r·\n)이 들어 있으면 그 칸을 비우고, 소제목이 그러면 그 섹션을 뺀다(작성자가 자른 글을 옮겨 적어 비밀값 앞부분이 보고서에 남는 일이 없게). 작성자에게는 노트처럼 외부 글 틀 안에 섹션마다 JSON 한 줄로 준다(모델이 쓴 글은 데이터). 작성자는 개요를 따라 보고서 전체를 한 단계로 쓴다(섹션 병렬 작성은 글이 끊겨서 하지 않음). 개요가 없으면(시간 부족·실패·읽을 수 없는 답) 예전 흐름 그대로다. 작성 단계 직전에 대화가 아직 Claude인지·연결이 있는지 다시 본다. 개요 단계를 마치면 그 결과(개요, 또는 없음)를 체크포인트(`state.outline`)에 저장해, 작성 중 재시작해도 개요를 다시 묻지 않는다. 체크포인트에는 열쇠 없는 모양(섹션마다 `[소제목, 질문, 분석할 점, 노트 id들]`)으로 둔다 — 저장 행의 비밀값 가림은 객체의 열쇠까지 보므로 `sections`로 시작하는 비밀값이 열쇠를 바꿀 수 있다(17차); `null`(물었고 없음)이 아닌 값이 읽을 수 없거나 지금의 노트로 다시 검사해 쓸 수 없으면(빈 개요, 이 작업의 노트가 아닌 id) 묻지 않은 것으로 보고 예산이 되면 다시 묻는다(18차). 개요 턴과 작성 턴의 질문·계획(제목·하위 질문)·노트(주장·구절·제목·위치)도 **각 턴을 보내기 직전에**(세션과 MCP 서버가 준비된 뒤 — `runStep`이 턴 글을 함수로 받아 그때 만든다, 19차; 개요 단계나 세션 시작을 기다리는 사이 등록된 비밀값도 가려지게) 지금 알려진 비밀값으로 칸마다 거친다 — 재시작한 작업의 체크포인트가 새 비밀값보다 오래됐을 수 있다(저장 행 재가림은 뒤에서 돈다). 이 저장은 재시작 때 다시 묻지 않게 하는 최적화일 뿐이라, 실패하면(데이터베이스가 잠깐 바쁨) 로그(`research.outline_unsaved`)만 남기고 작성자로 넘어간다 — 나중에 재시작하면 개요를 한 번 더 물을 수 있다(리뷰 15차, 8차의 "작성자를 시작하지 않음"을 대신함). 그사이 중지됐으면 거기서 끝난다. 작성자 턴을 만들기 직전에 개요를 **지금 알려진 비밀값**으로 칸마다 거친다(`maskOutline` — 소제목·질문·분석할 점을 글로만 가리고 구조와 노트 id는 그대로, 같은 규칙으로 다시 검사해 못 쓰게 되면 개요 없이): 체크포인트에서 이어 온 개요도 시작 뒤 저장 행 재가림을 기다리지 않고 가려지며, 객체 전체를 깊게 가리지 않으므로 `sections`로 시작하는 비밀값이 열쇠를 바꿔 개요가 깨지는 일이 없다.
- **해석도 인용한다.** 작성자 지침(`writer.md` v5)은 섹션마다 무엇이 바뀌었나·왜 중요한가·무엇과 비교되나를 설명하고, 마지막 `## 시사점`에 독자의 처지별 할 일을 쓰게 한다. 해석·조언 문장도 근거가 된 사실의 인용 번호를 붙여야 하며, 검사 규칙은 바뀌지 않았다 — 확인된 표시가 없는 문장은 해석이든 사실이든 지워진다. 표·코드·그림은 예전처럼 쓰지 않는다.
- **출처 묶기.** 표시 번호는 (출처, 구절)이 아니라 출처마다 하나다. 작성 보고서와 대체 보고서가 같은 열쇠(`reportSourceKey`)를 쓴다: 파일은 id, 웹은 최종 주소를 참고문헌과 같은 `urlKey`로(조각 `#…`은 빼고 질의는 남김), 주소가 없으면 출처 id. 붙어 있거나 공백만 사이에 둔 표시(`[1] [3]`)는 한 묶음이고, 같은 번호가 되면 한 번만 쓴다. 출처 열쇠는 크롤러가 확인한 **저장된 최종 주소**의 `urlKey`다 — 따로 가져온 두 페이지(`?q=a\b`와 `?q=a%5Cb`)는 두 출처로 남고, 같은 최종 주소를 다른 가져오기로 얻었으면 한 출처다(IPv6 주소도 같다).
- **저장되는 보고서에는 모든 글이 그대로(리뷰 12차 결정).** 페이지·파일·사용자·모델에서 온 글은 어느 것도 이스케이프 문자를 끼워 넣지 않고 그대로 저장한다 — 나중에 등록한 비밀값을 저장된 아티팩트의 재검사가 통째로 가릴 수 있게. 그래서 출처의 제목(링크 안에서도)·사이트·파일 이름·위치·구절, 보고서 제목, "한계"의 하위 질문, 대체 보고서의 하위 질문 제목과 구절은 모두 **코드 글자**(가변 길이 백틱)로 쓴다: 두 렌더러가 그대로 보여 주므로 자동 링크·수식·목록 기호도 생기지 않는다. 글은 줄바꿈만 공백으로 바꾸고 **자르지도, 공백을 줄이거나 다듬지도 않는다**(13차) — 저장 단계에서 이미 길이가 정해져 있다(출처 제목 300, 사이트 120, 구절 500, 하위 질문 300, 보고서 제목 120, 주소 2048). 자른 글 끝에 남은 비밀값 앞부분은 재검사가 찾지 못하기 때문이다. 표시는 CSS가 맡는다: 보고서 페이지의 인라인 코드는 `white-space: pre-wrap`(두 칸 공백·U+3000이 그대로 보임)과 `overflow-wrap: anywhere`(모바일에서도 줄바꿈) — 서버 `MARKDOWN_STYLE`과 앱의 `.artifact-doc`에만, 코드 블록·채팅은 그대로. 출처 링크는 **저장된 주소 그 자체**가 http(s)이고 URL 표준 형태(`new URL(주소).href`가 같은 글)이며 `<…>` 안에 그대로 넣어 같은 주소로 나올 때만 건다; 마크다운이 달리 읽을 글자(엔티티 꼴 `&…;`, `\`, `<`, `>`, 공백·줄바꿈)가 있거나 정규화하면 달라지는 주소(`a b`, `a\b`, `<x>`, IPv6 등)는 링크를 걸지 않고 **원래 주소를 통째로** 코드 글자로 보여 준다(바뀐 주소로 연결하지 않음). 보이지 않는 문자를 넣던 방식과 백슬래시 이스케이프는 복사·비밀값 가림을 깨서 뺐다.
- **노트 상한은 45개 그대로.** 작성 단계의 인용 상한이 50개라, 모든 노트를 인용하고 실패한 인용을 고칠 여유를 남긴다.
- **줄인 범위(리뷰 6차 뒤 결정).** 처음에는 근거 번호가 붙은 분석 블록(`> 💡 분석`)과 GFM 표를 허용하고, 그 검사를 위해 보고서 마크다운을 허용 목록으로 정규화했다. 리뷰 6차까지 분석 블록·표·정규화에서 인용 번호가 다른 주소로 이어지거나 근거 없는 수치가 남는 경로가 계속 나와, 사용자 결정으로 셋 다 뺐다. 보고서 정리(`cleanReport`)와 `packages/shared/src/citations.ts`는 출처 묶기를 빼면 #211 그대로다. 채팅 #202 결과를 지키는 고정 말뭉치 시험은 회귀 방지로 남겼다.
