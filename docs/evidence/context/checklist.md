# 대화 중 런타임 전환 실런타임 확인 (#45 완료 기준, 수용 기준 8)

자동 시험이 다루지 못하는 부분만 남긴다: 실제 런타임(Claude Code, Codex)이 넘겨받은 맥락으로 앞 대화 내용을 알고 답하는지, 전환 직후 첫 토큰이 얼마나 걸리는지. 자동 시험이 확인한 것은 다음과 같다.
- 이어가기 조건 각각(런타임·연결·revision·마지막 메시지·요약), 모델만 변경(`setModel` / 새 세션), 참조 목록, 요약 임계·재사용·구분선·실패·모델 권한·비밀 — FakeRuntime(`apps/server/test/context.test.ts`)
- Claude→Codex→Claude 왕복, 수정 후 재전송, 재생성, 연결 변경, 모델만 변경, 요약 이후 재개 — 두 런타임의 녹화 형식 재생(`apps/server/test/context-replay.test.ts`). 각 run마다 런타임이 받은 맥락(어댑터가 실제로 보낸 프롬프트를 되읽은 것)이 서버 원본과 같다.

대화 내용은 적지 않는다(질문 종류, 결과, 시간만).

**사전 조건**
- macOS에서 운영 빌드(`pnpm build && pnpm start`), 실제 런타임 연결(`docs/ops.md` §11): 관리자 본인 Claude 연결과 Codex(API 키 또는 ChatGPT 로그인), 두 연결 모두 테스트 `passed`.
- 어른 계정 하나. Claude는 Opus 5.5와 Sonnet 5.5 모두 허용(§20.2).

## F. 전환 후 첫 토큰 p95 (`docs/acceptance.md` §3, #40 규격)
측정 스크립트(`scripts/perf/`, #38)는 아직 없다. 그 전까지 아래 방법으로 잰다.
- 조건: 운영 Mac, 다른 무거운 작업 없음, 메시지 20개 대화(도구 호출 없는 짧은 문답), 방향별(Claude→Codex, Codex→Claude, 모델만 변경) 20회.
- 한 번: 칩으로 전환 → 고정 프롬프트 `한 문장으로 인사해줘` 전송 → 응답 첫 글자가 화면에 보일 때까지.
- 재는 방법(브라우저 개발자 도구): 콘솔에서
  `performance.mark("send")`를 전송 직전에 찍고, 첫 글자가 보이면 `performance.measure("ft", "send")`. 또는 Playwright로 전송 클릭 시각과 `[data-testid=message]` 마지막 항목에 첫 글자가 생긴 시각(DOM 관찰)의 차.
- 서버 쪽 참고값: 로그 `run.finished`의 `durationMs`는 run 전체 시간이라 첫 토큰이 아니다. 첫 토큰은 화면 기준으로만 판정한다.
- 판정: 방향별 20개 중 19번째로 느린 값(p95) ≤ 6초. 결과에 커밋·모델·시각을 적는다.

## H. 전환 뒤 파일·출처·아티팩트 (#53, 수용 기준 8·11)
자동 시험(`apps/server/test/runtime-switch.test.ts` 녹화 재생, `e2e/runtime-switch.spec.ts`)이 두 방향 모두 확인한 것을 실제 모델로 한 번씩 본다. 방향마다(Claude→Codex, Codex→Claude) 새 대화로.
1. [ ] PDF(`fixtures/extract/report.pdf`)와 HWP(`fixtures/extract/assignment.hwp`)를 올리고 `두 문서를 비교해 줘. 인용을 붙여서` → 인용에 "report.pdf · 12쪽", "assignment.hwp · 3번째 표 …"가 붙는다.
2. [ ] 칩으로 런타임을 바꾸고 `아까 그 HWP 파일에서 제출 방법 부분을 다시 인용해 줘` → 파일을 다시 올리라고 하지 않고, 같은 파일 이름·위치로 확인된 인용(원문 구절 확인).
3. [ ] 새 대화에서 웹 자료를 인용하는 질문(예: 최근 반도체 수출 기사) → 바꾼 뒤 `방금 그 기사에서 한 문장만 다시 인용해 줘` → 같은 출처(같은 URL)로 확인된 인용.
4. [ ] 마크다운 아티팩트를 만들게 하고(`관심 종목 메모를 아티팩트로 만들어 줘`) → 바꾼 뒤 `그 메모에 목표가 25만원 줄을 추가해 줘` → 같은 아티팩트의 v2(패널의 버전 목록에 v1·v2), 앞 내용이 그대로.
5. [ ] 다른 가족이 위 대화를 공유받아 "이어서 대화하기" → 런타임을 바꾸고 2·3·4를 다시 → 파일·아티팩트는 사본으로 확인된 인용·v2, 출처는 다시 가져온 뒤 확인된 인용(가져오지 않고 인용하면 ⚠️). 원래 대화의 아티팩트는 그대로.
