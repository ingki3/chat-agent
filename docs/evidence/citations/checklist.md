# 인용 검증 실런타임 확인 (#25 완료 기준)

자동 시험이 다루지 못하는 부분만 남긴다: 실제 런타임(Claude Code, Codex)이 실제 웹 페이지를 가져와 `cite`를 부르고, 답변 아래 출처 목록과 ⚠️가 맞게 보이는지. 자동 시험이 확인한 것은 다음과 같다.
- 정규화·오탐 없음·범위(다른 대화·다른 사용자 → `unknown_source`)·문단 규칙(`apps/server/test/citations.test.ts`)
- FakeRuntime과 두 런타임의 녹화 형식 재생으로 같은 네 시나리오 — 충돌·자료 부족·부분 누락·기존 출처 재사용(`apps/server/test/citation-runs.test.ts`)
- 화면 ⚠️ 표시(`apps/web/test/citations.test.ts`), 데스크톱 hover·모바일 탭 미리보기(`e2e/citations.spec.ts`)

구절·페이지 내용은 적지 않는다(질문, 결과, 상태만).

**사전 조건**
- macOS에서 운영 빌드(`pnpm build && pnpm start`), 실제 런타임 연결(§11): 관리자 본인 Claude 연결과 Codex(API 키 또는 ChatGPT 로그인).
- 웹 도구 켜짐(§17.1). 아들 계정(`youth: true`)과 어른 계정 하나.

## A. 충돌하는 출처 (두 런타임 각각)
1. [ ] 새 대화에서 `🔎 자료 조사`를 켜고 `이번 달 반도체 수출 증가율을 두 군데 이상 출처로 비교해 줘` → 도구 `web_search`·`web_fetch`·`cite`가 쓰인다.
2. [ ] 문장 끝에 `[1]`·`[2]`가 있고, 출처 목록에 제목·사이트·날짜·URL·"원문 구절 확인"이 보인다.
3. [ ] 수치가 다르면 답변이 그 사실을 출처별로 쓴다(FR-5.4). 최신 사실에 날짜가 있다.
4. [ ] 데스크톱: `[1]`에 마우스 → 인용 구절과 "원문 열기". 눌러서 연 원문 페이지에 그 구절이 있다.
5. [ ] 휴대폰: `[1]`을 누르면 같은 미리보기, 다시 누르면 닫힌다.

## B. 자료 부족
1. [ ] 자료 조사 모드에서 `아주 최근의 덜 알려진 주제(예: 지역 소식)`를 묻는다 → 출처가 하나뿐이거나 없으면 "출처가 충분하지 않아요"처럼 말하고 단정하지 않는다.
2. [ ] 검색 결과만 인용하려 했다면 그 표시는 `[n⚠️]`이고 목록에 "⚠️ 출처를 가져오지 못했어요".

## C. 부분 누락·실패 표시
1. [ ] 웹 자료를 쓴 답변에 인용 없는 본문 문단이 있으면 그 문단이 ⚠️로 표시되고 "⚠️ 일부 내용에 출처 표시 없음"이 보인다(제목·목록 머리말·면책은 표시되지 않음).
2. [ ] 어떤 표시든 ⚠️ 상태가 "원문 구절 확인"처럼 보이는 경우가 없다(목록·미리보기·표시 모두).

## D. 기존 출처 재사용
1. [ ] A의 대화에서 이어서 `앞에서 본 첫 기사에서 원인이 뭐라고 했지?` → `sources_list`와 `cite`가 쓰이고(새 `web_fetch` 없이), 표시가 "원문 구절 확인"이다.
2. [ ] 다른 대화에서 A의 출처를 인용하게 시켜도(`앞 대화의 그 기사 인용해 줘`) 확인됨으로 보이지 않는다.
