# 금융 도구 실계정·실런타임 확인 (#30 완료 기준)

자동 시험이 다루지 못하는 부분만 남긴다: 실제 데이터 원천(네트워크)과 실제 런타임(Claude Code, Codex)이 금융 도구를 부르고, 답변 아래에 출처·기준 시각·면책이 붙는지. 자동 시험이 확인한 것은 다음과 같다.
- 도구별 합성 응답 재생 스냅샷, 토요일 → 금요일 종가, 휴장일·조기 폐장(`apps/server/test/finance.test.ts`)
- 두 런타임의 녹화 형식 재생으로 "AAPL, 005930 현재가" → 출처·기준 시각·면책(`apps/server/test/finance-runs.test.ts`)
- 화면 표시(`e2e/finance.spec.ts`, FakeRuntime)

값(키, 연락처 메일, 쿠키)은 적지 않는다.

**사전 조건**
- macOS에서 운영 빌드(`pnpm build && pnpm start`), 실제 런타임 연결(§11): 관리자 본인 Claude 연결과 Codex(API 키 또는 ChatGPT 로그인).
- 공시까지 확인하려면 `.env`에 `OPENDART_API_KEY`, `SEC_USER_AGENT`(§19.1) → 서비스 재시작.
- 아내 계정(어른, 기본 권한), 아들 계정(`youth: true`, 기본 권한).

## A. 두 런타임에서 "AAPL, 005930 현재가"
1. [ ] 아내 계정, 새 대화, 런타임 Claude Code: `AAPL, 005930 현재가` → 도구 `us_quote`·`kr_quote`가 쓰인다(도구 n개 사용).
2. [ ] 답변 아래 금융 메모에 `Yahoo Finance · … ET 종가|장중`과 `네이버 증권 · … KST 종가|장중`이 보이고, 면책 문구가 있다.
3. [ ] 답변 본문의 숫자 옆에도 출처·기준 시각이 있으면 ⚠️가 없다. 없으면 ⚠️ "출처·기준 시각이 빠진 부분"이 보인다(어느 쪽이든 메모의 출처는 맞아야 한다).
4. [ ] 같은 질문을 런타임 Codex로 → 2·3번과 같다.
5. [ ] 토요일(또는 휴장일)에 1번을 한 번 더 → 기준 시각이 **금요일(최근 거래일) 종가**다(`kind: close`, 15:30 KST / 16:00 ET).
6. [ ] 평일 장중(09:00–15:30 KST)에 `005930 현재가` → `장중` 표시, 네이버 지연 표시가 데이터와 같다.

## C. 아들 계정
1. [ ] 아들 계정에서 `AAPL 현재가` → 금융 도구가 쓰이지 않는다(도구 목록에 없음). 답변이 숫자를 지어내지 않고, 숫자를 말하면 출처가 없다는 것을 밝힌다.
2. [ ] 관리자가 `PUT /api/admin/users/<아들>/skills {"skills": ["kr-stock-skill"]}` → 아들의 `005930 현재가`가 `kr_quote`로 답한다. `AAPL 현재가`는 여전히 금융 도구 없이 답한다. 원래대로 `"all"`로 돌린다.
